# Retail Product & Availability Analytics

Product-level analysis of **on-shelf availability**, lost sales, **pricing** (Active prices only), sales and stock health
for a grocery retailer that supplies its stores from six depots. Built with **SQL** and laid out as a **Power BI** report
with a star-schema data model.

> **Synthetic data.** Products, depots, prices and weekly stock were generated by `01. Dataset/generate_dataset.py`
> (seed 31). No real retailer data is used. The project mirrors the kind of depot product-availability and pricing
> reporting I have built in Power BI, rebuilt on made-up data so it can be shared.

## Business questions
1. How available are products by depot, category and week, and how much demand do we lose?
2. Which products are most often out of stock?
3. What is the current Active price of each product, and how do unit sales react to price changes?
4. Is stock at the right level at year end (weeks of cover), and are delisted products still holding stock?
5. Are active products ranged in every depot?

## Key findings
| # | Finding | Evidence |
|---|---|---|
| 1 | Availability was **97.2%** and **7.4%** of demand was lost, worth about **₹11.1 Cr** at Active prices. | `01`, `03` |
| 2 | **Madurai** is the weakest depot: **93.5%** availability and **14.8%** of demand lost, against 98.9% and 4.7% at Chennai North. | `01`, `08` |
| 3 | Frozen (**94.9%**) and Fresh Produce (**96.5%**) have the lowest availability; Fresh Produce has the largest lost value (**₹2.5 Cr**). | `02`, `04` |
| 4 | After a price **increase** (avg 7.6%), weekly units fell **9.8%** over the next 4 weeks; after a **cut** (avg 7.3%), units rose **10.3%**. | `06` |
| 5 | **118 products (44%)** make 80% of revenue (class A): these should be protected first when stock is short. | `12` |
| 6 | At year end **161 active lines (11.8%)** had less than 1 week of cover, and **23 delisted products** still held **10,879 units** in depots. | `09`, `10` |
| 7 | **124** depot listings are missing for **100** active products (ranging gaps). | `11` |

**Pricing rule.** The raw price file has **83 Inactive** (cancelled or draft) rows. Only **Active** rows are used for prices,
revenue and lost value. Mixing them in would put wrong prices on the report.

## Data cleaning
| Table | Issue / action | Count |
|---|---|---:|
| Products | Category text set to title case | 8 |
| Depots | No issues found | 0 |
| PriceHistory | Inactive (cancelled / draft) price rows removed: only Active prices are used for pricing | 83 |
| WeeklyStockSales | Exact duplicate rows removed | 219 |
| WeeklyStockSales | DepotID trimmed and upper-cased ('d3 ' -> 'D3') | 150 |
| WeeklyStockSales | Duplicates found after fixing DepotID removed | 1 |
| WeeklyStockSales | Negative ClosingStock (system error) set to 0 | 90 |
| WeeklyStockSales | Added InStock (closing stock > 0) and LostUnits (demand not met) | 74,532 |

## SQL scripts
| Script | Question |
|---|---|
| `01_Availability_By_Depot.sql` | What is on-shelf availability by depot, and how much demand was lost? |
| `02_Availability_By_Category.sql` | Which categories have the lowest availability? |
| `03_Weekly_Availability_Trend.sql` | How did availability move week by week through 2024? |
| `04_Worst_Availability_Products.sql` | Which active products are most often out of stock? |
| `05_Current_Active_Price.sql` | What is the current selling price of each product, and how often did it change in 2024? |
| `06_Price_Change_Impact.sql` | What happens to unit sales in the 4 weeks after a price change? |
| `07_Sales_By_Category.sql` | What are units, revenue and average selling price by category? |
| `08_Lost_Sales_Depot_Category.sql` | Where is lost-sales value concentrated (depot x category)? |
| `09_Weeks_Of_Cover_Year_End.sql` | At year end, how many active product-depot lines are understocked or overstocked? |
| `10_Delisted_Products_Holding_Stock.sql` | Which delisted products were still sitting in depots in their last recorded week? |
| `11_Ranging_Gaps.sql` | Which active products are not stocked in every depot? |
| `12_Product_ABC_By_Revenue.sql` | How is revenue spread across products (ABC classes)? |
| `13_Brand_Mix.sql` | What share of revenue comes from own-label products in each category? |

Techniques used: date-range joins (price valid in a week), CTEs, window functions (`ROW_NUMBER`, running totals, share of total),
conditional aggregation (pivot), before/after comparison and banding. Written for SQLite; notes for SQL Server / MySQL are in `00_Create_Tables_And_Load.sql`.

## How to run
```bash
pip install pandas numpy
cd "01. Dataset"
python generate_dataset.py
python clean_dataset.py
cd ..
sqlite3 retail.db < "02. SQL Scripts/00_Create_Tables_And_Load.sql"
sqlite3 -header -csv retail.db < "02. SQL Scripts/01_Availability_By_Depot.sql"
```
